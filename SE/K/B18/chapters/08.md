## The problem you are learning to solve

Imagine the regional mobility council meets after an emergency drill. Agencies individually meet many of their own targets, yet some residents still cannot reach essential care. A sponsor wants a decisive engineering answer and a single performance number. You are responsible for making the inquiry sufficiently precise to support action without pretending away divided responsibility, incomplete evidence or affected people.

This week's question is **federated sos modeling, simulation, interoperability, and credibility**. The key conceptual move is *a federation is a model of models with contracts*. The decision is not merely whether an artifact can be drawn: it is whether the claims made by that artifact survive a realistic change in authority, timing, evidence or public consequences. We therefore work from a real decision question toward an explicit representation, then test where the representation breaks.

## The central concept, built carefully

A road simulator runs on one-minute steps while ambulance dispatch operates on events. Define the common clock, exchange events, state ownership, latency and failure behavior before relying on their joint output. A federation without time semantics can generate impossible arrivals.

Design an experiment matrix separating scenario variability from model uncertainty. Rerun synchronized seeds after changing event-order precedence to test whether a claimed evacuation improvement is a scheduler artifact.

The engineering reasoning should move in a disciplined order. First name the observed or desired outcome, the boundary, the actors who have the right to act, and the time horizon. Next identify the mechanism hypothesized to link an intervention to that outcome. Then choose a representation—network, causal loop, interface contract, process model, probability table, capability map or deliberative inquiry—whose assumptions match the phenomenon. Finally specify evidence able to disconfirm the model. That last step matters because a persuasive representation can still be false, incomplete, or legitimate for only a narrow class of decisions.

### Federated simulation must preserve constituent assumptions

Federation allows independently developed models to participate in a shared experiment, but it introduces a second level of validity questions. A transport model may update every second while a hospital capacity model updates hourly. A network model may treat failure as independent while a power model explicitly represents shared infrastructure. Coupling these models does not automatically make their combined predictions credible.

The federation contract must state exchanged quantities, units, coordinate systems, clock synchronization, event ordering, initialization, and failure semantics. It should also record which results each constituent model was validated to support. A coupled experiment can reveal emergent interactions, but those interactions may arise from an artificial interface or numerical coupling artifact. Engineers should verify simple federation scenarios with known outcomes and distinguish robust qualitative insights from precise forecasts that depend on questionable assumptions.

## Graduate depth: federated simulation and compositional credibility

### A federation is more than a collection of accurate models

Federated modeling connects constituent simulators that may have independent owners, clocks, abstraction levels, and update cycles. Each model can be valid for its own purpose while their composition is invalid for the mission being studied. A traffic simulator might use minute-level flows, a communications simulator millisecond packet timing, and an emergency-policy model discrete decision events. Coupling them requires explicit semantics for time advancement, event ordering, state exchange, initialization, and how uncertainty crosses model boundaries.

Let subsystem state be `x_i` and exchanged input be `u_i`. A federated model approximates dynamics `dx_i/dt=f_i(x_i,u_i,t)` or discrete transitions `x_i(k+1)=F_i(x_i(k),u_i(k))`. Exchanged values can arrive after delays, and their meaning must specify sampling, averaging, prediction, or held-value behavior. A zero-order hold of a rapidly changing signal introduces error; exchanging values from incompatible coordinate frames can introduce systematic bias; inconsistent rollback policies can produce impossible causal sequences. An integration test that only demonstrates message delivery does not establish that the coupled dynamics are right.

### Verification must be layered

Start with interface conformance: schemas, units, ownership, message timing, fault behavior, and security controls. Then test numerically controlled composite cases whose expected behavior is understood, such as conservation of passengers across a dispatch-to-vehicle boundary. Compare a high-fidelity joined model with simplified analytic bounds where possible. Finally assess mission-level credibility using relevant operational data or carefully justified surrogate evidence. Validity is *compositional* only when the assumptions that supported the constituent models remain compatible in the composition.

Error may amplify through feedback between constituent models. A small communication-delay error can cause dispatch retries, duplicate resource assignments, and cascading queue growth. If the federation is used to select architectures, vary coupling timestep, timing jitter, synchronization modes, missing-data assumptions, and constituent-model fidelity. A stable answer under one orchestration is weaker evidence than a result robust to reasonable orchestration choices. Record the federation configuration with the same rigor as the model versions.

### Authority and reproducibility across organizations

An SoS lead often cannot inspect the internals of proprietary or independently governed simulators. A black-box contract should therefore identify intended use, validated input range, output units, error bounds where available, version, data rights, and conditions requiring requalification. A model change notification must travel to consumers whose results depend on the changed behavior. Provenance is a prerequisite for reconstructing a federation run, but not by itself a guarantee of scientific validity.

For Northstar, suppose a regional dispatch federation reports robust response time under a network-outage scenario. Before acting, ask whether the constituent vehicle models simulated local queuing, whether emergency policy accepted delayed messages, whether shared infrastructure outages were correlated, and whether all partners used compatible demand scenarios. The defensible deliverable is a bounded mission-level claim plus a set of remaining uncertainties. Federation expands coverage of a complex system, but can also multiply hidden assumptions; credibility work must expand with it.

### Where this method stops working

Successful interface execution is not validation against observed operational behavior or a demonstration that the model is credible for a new decision.

A responsible engineer should separate *model correctness* (the math or logic follows from its premises), *model credibility* (the premises are supported for this use), and *decision legitimacy* (the process respects authority, rights and affected parties). Passing the first test does not guarantee the other two. In particular, neither a hypothetical exercise nor an attractive decision matrix certifies an operational regional service.

## Reading the broader system

The three Phase 5 books offer complementary lenses. The systems-of-systems lens asks which independently managed constituents must cooperate and what technical evidence can travel between them. The enterprise lens asks how resources, incentives, governance and institutional history shape that cooperation. The critical-complexity lens asks whose interpretation dominates, which boundaries exclude harms and when no single technical objective deserves priority. Use all three when a proposed solution changes both technology and public obligations. Their explanations can disagree without one being automatically mistaken: they may be answering different questions.

## Step 03 — NS-SOS18.1 regional emergency access engineering laboratory

### Federated simulation with explicit credibility claims

A federated SoS simulation may involve independently operated rail timetables, campus-fleet availability, hospital receiving constraints, communications delay and patient/mobility demand. A coherent experiment needs a **time contract**: all partners agree the model epoch, time step or event timestamps, synchronization/lookahead, message ordering, rollback policy, units, object ownership, interface schemas and representation of unavailable data. Passing one message over an API is not HLA time-management or FMI/RTI conformance.

The [Python implementation](../tools/step03_book18_sos.py) deliberately does not simulate agents or asynchronous events. Instead it computes a deterministic four-hour aggregate screening value under four *joint* event scenarios. Treating a grid outage as an explicit scenario rather than multiplying independent rail and bus outage probabilities prevents one particular independence error, but the scenario weights themselves are arbitrary. Each policy's reported weighted pass fraction is \(C_p=\sum_s q_s\,\mathbf1[g(p,s)]\), where \(q_s\) are stipulated scenario weights and \(g\) combines throughput, freshness and interface conformance.

Example: the unmitigated policy passes only normal, so \(C_0=.55\). Backup power additionally passes grid, so \(C_{backup}=.55+.20=.75\). Integrated passes all four, so \(C_{integrated}=1.00\). This is **scenario coverage under a fixed suite**, not the probability of successful real service. Running the [compound scenario](../case/computed-evidence.json), outside that distribution, makes even integrated policy fail; the model is therefore unfit for unqualified extrapolation.

### Federation-design exercise with explanation

**Exercise.** A rail federate publishes revised capacity at simulation time 07:59 but the dispatch federate processes it after using an older 08:00 value. What has failed? **Solution.** Event order / time coherence has failed; examine timestamp semantics, lookahead and queue ordering before claiming that rail capacity was accurately represented. A replayability check should compare identical inputs, seeds, time contracts and outputs. For a high-consequence use, independently validate against field drills, and document which federates were actually verified.
