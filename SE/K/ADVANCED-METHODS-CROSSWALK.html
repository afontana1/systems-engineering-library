Follow a complete evidence chain

  1. Define the claim and configuration. State mission outcome, stakeholder populations, requirements, operating conditions, and source revision. Start with mission claims.
  2. Check model and numerical methods. Separate data uncertainty, model uncertainty, sampling error, and solver error. Start with model credibility and dynamics and numerical stability.
  3. Test constraints and interfaces. Produce negative examples, dependent-failure checks, and contract traces. Start with interface contracts and resilience.
  4. Assess social and distributed consequences. Examine human workload, autonomous constituent authority, accessibility impacts, and causal confounding. Start with human integration and critical intervention.
  5. Review evidence and approval separately. Link each verified method result to a valid configuration and independently review missing consent, authority and acceptance conditions. Start with provenance and assurance claims.

Four distinctions that cannot be collapsed

Observed fraction versus probability: a finite sample proportion is not a validated population rate; uncertainty bounds require assumptions about sampling and independence.

Reliability versus availability: survival over an interval differs from readiness at a moment; shared-cause failures invalidate naive independence products.

Verification versus validation: passing calculations and code tests show conformance to the implemented model, not fitness of the model for the intended real-world use.

Technical feasibility versus permission: meeting a synthetic performance threshold does not satisfy safety, accessibility, labor, privacy or governance requirements.
