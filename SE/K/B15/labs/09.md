# Hypothetical Lab 09 — Increment-level assurance

**Course:** EN.645.780 — Agile Systems Engineering  
**Read first:** [Chapter 09](../chapters/09.md) · **Assessed assignment:** [Original Week 9](../../../C/P4/EN645780.md)

## Situation and objective

Northstar's fictional program review committee has received a proposed change involving **build quality, safety, security, and verification into every increment**. The program lead wants an immediate favorable recommendation, the safety lead requires an intact evidence chain, and the operator demands a measurable benefit. Your task is to avoid a purely procedural response and build a bounded, reviewable engineering decision.

**Practice question:** Release gate: formulate minimum independent checks for a cancellation-timeout change and define blockers.

## Provided evidence and constraints

Northstar passes 50 nominal dispatch tests but has no evidence that timeout cancellation leaves only one active booking. Release must be conditional until the safety invariant is tested.

- Configuration: instructional Northstar baseline P4-W09; all observations are synthetic and must not be presented as measured field evidence.
- Required guardrails: traceability to the released requirement revision; safety and security exceptions must be reviewed; inaccessible demand cannot be discarded to inflate a service metric.
- You have authority to recommend an experiment, not to bypass a release gate or certify the system.
- An alternative explanation must be recorded and actively tested rather than dismissed.

## Investigation procedure

1. **State the decision.** Name the decision maker, available options, consequence of being wrong, and deadline. Define a testable success claim.
2. **Map the mechanism.** Diagram the causal chain or model relationships described in the chapter. Record inputs, units, release identifiers, and who owns each assumption.
3. **Calculate or trace a baseline.** Reproduce the supplied nominal result. Distinguish direct observation, derived value, and illustrative assumption.
4. **Stress the logic.** Apply the adverse change below. Note which constraints become active, which evidence becomes stale and which stakeholders are affected.
5. **Propose a controlled response.** Specify the smallest legitimate experiment, evaluation criteria, independent reviewer, and stop rule.
6. **Defend the recommendation.** Present one argument in favor and one credible counterargument. Explicitly identify evidence that would reverse the recommendation.

### Change challenge

A deployable increment requires complete evidence for claims affected by the change, not completion of every conceivable system test. Negative tests must cover timeouts, duplicate messages, retry behavior and recovery. Keep simulation vs hardware vs operations distinctions explicit.

## What to submit

Create a one- to three-page decision note (Markdown is fine) containing a decision table, the key calculation or trace, assumptions, uncertainty, configuration, guardrail status and next evidence-gathering action. Include one diagram or dependency map and a compact evidence index. Do not copy the reference critique as your answer.

### Reference critique — view only after attempting

<details><summary>Expand reference reasoning</summary>

A defensible answer begins with **assurance needs to be incremental too**, not with a preferred tool or ceremony. Define a minimum evidence bundle for each increment: identified hazard claims, changed requirements, executed tests, independent review, and released configuration hashes. Integrate negative and exception tests as early as nominal ones. A safety case is a continuously maintained argument with evidence, not a document produced after the code freezes.

**Stress-case interpretation:** Release gate: formulate minimum independent checks for a cancellation-timeout change and define blockers. An unqualified approval would be inappropriate if critical evidence, stakeholder impact, or configuration ownership remains unresolved. A conditional decision can be valid when it specifies the next test, independent reviewer and stop rule. Compare your reasoning against this structure and revise your memo where the evidence chain is incomplete.
