Conceptual explanation

From necessary functions to feasible products

Physical architecture identifies realizable elements—vehicles, controllers, networks, terminals, humans, facilities and procedures—and how they cooperate. Allocate each function to at least one responsible element, but preserve important shared responsibilities explicitly. A single function may span a passenger app, cloud service and onboard controller; the allocation matrix must reveal that interaction rather than arbitrarily choosing one box.

An architecture choice is justified by quality attributes: latency, safety, availability, cost, maintainability, security and upgradeability. Different partitions change which interfaces are local and which traverse organizations or networks. Centralized dispatch can simplify global optimization but creates connectivity dependence. Local autonomy can improve degraded operation but increases onboard computation and software assurance responsibilities. Use constraints and trade studies to evaluate rather than rely on personal aesthetic preference.

Interface control as a technical agreement

An interface control document (ICD) defines a mutually understood contract between producers and consumers. Minimum data fields: purpose, owners, physical/logical boundary, exchanged items, schema and units, protocol and version, timing, availability/error assumptions, abnormal behavior, safety/security controls, change process and verification. For a message protocol, a version mismatch is not 'just software'; it may become an operations or safety defect.

A controlled interface is checked bidirectionally. Producer-side testing proves it emits valid data; consumer-side testing proves it handles valid and invalid data. An end-to-end test checks combined behavior. Claiming compliance because each component tested against its own private assumptions invites integration failures.

Make architecture changeable

Mark high-risk design decisions with rationale and reversibility. A tightly coupled architecture may make every software update a fleet-wide event; a loose interface may permit independent upgrades but require stronger compatibility testing. The goal is not maximum modularity; it is sufficient cohesion inside components and sufficiently well-specified connections between them.

Worked example: reason through the case

Example: Function 'route assignment' is allocated to Dispatch Service D1, while 'execute assigned route' is allocated to Vehicle Controller V1. ICD-07 specifies route-ID string, map-version hash, stop sequence, epoch timestamp and expiration in UTC seconds. Onboard software rejects a stale command or mismatched map version and reports a reason. Test producer and consumer separately, then perform an integration test under a delayed network connection.

  2. List four ways identical message names can still produce an integration failure.
  3. Describe an allocation matrix entry for "notify rider of trip cancellation".

A failure mode to recognize

Mistake: modeling interfaces as undirected connectors without ownership, protocol or failure behavior.
