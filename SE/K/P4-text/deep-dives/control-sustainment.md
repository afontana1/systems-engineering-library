# Engineering process control and sustainment

**Concept essay · EN.645.783 · Phase 4 companion**

*Illustrative calculations and scenarios use synthetic data; do not treat them as certified operational evidence.*

A process improvement is not finished when a pilot dashboard turns green. Sustainment requires approved process definitions, trained performers, versioned evidence requirements, monitoring ownership, exception paths, and response rules. Treat the future-state process as a controlled engineered system with configurable behavior and measurable health.

### Control plan structure

For each metric identify: definition; source; frequency; responsible owner; expected envelope; escalation trigger; triage steps; evidence retained; and corrective-action authority. Not every data excursion is a defect. Use sensible statistical rules where distribution and independence assumptions are met, plus explicit threshold rules for critical escapes that need no statistical waiting.

### Worked case

After reducing average lead time by 20%, Northstar observes one critical release missing required cybersecurity evidence. A leader focused only on the average might celebrate. The control plan instead blocks further releases of that configuration class, performs a bounded audit of similar cases, and initiates causal investigation while maintaining the improvement program’s other measures.

### Design for human behavior

Metrics create incentives. A target for “zero late reviews” may encourage moving cases to an excluded state. Regularly inspect boundary shifts, unlogged effort and reviewer disagreements. Include operator and supplier feedback to spot effects quantitative dashboards miss.

**Exercise.** Write a one-page reaction plan covering data anomaly, rework spike and critical safety-evidence escape. Which events require immediate containment, which merit trend monitoring, and who authorizes each action?
