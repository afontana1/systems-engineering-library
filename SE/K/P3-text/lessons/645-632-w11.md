## The idea in context

A profile or metamodel extension creates new meaning only if its semantics are precise. Custom stereotypes should include valid targets, required tags, types and constraints. Automated rules can find duplicate identifiers, missing provenance, incompatible units and broken traces, but they cannot infer stakeholder intent without a sound specification. Generated matrices need a revision stamp and a link to underlying element IDs.

## Worked reasoning: apply it to the shuttle case

A stereotype «CriticalMeasure» requires `unit`, `threshold`, `owner`, `source` and `method`. A query rejects the incomplete element “Boarding wait” missing a clock-start definition, even if it appears correctly on a diagram.

**Assumption to challenge:** Automating an ambiguous modeling rule and calling a zero-error report model validation. Record what observation or test would expose this failure before using the result in a decision.

## Test understanding before reading the answers

The next three questions are adapted from the **original guide's Week 11 knowledge check**, with its answer guidance retained so you can learn and self-check in one place.

1. What is a profile?
2. What is a model library?
3. What is validation severity?

<details><summary><strong>Reveal guided answers</strong></summary>

1. **What is a profile?** A mechanism for extending a modeling language through defined stereotypes, properties, constraints, and notation without changing the base metamodel.

2. **What is a model library?** Reusable model content such as value types, definitions, patterns, requirements, or domain elements that may avoid language extension.

3. **What is validation severity?** The classified consequence and required response when a model rule is violated.

</details>
