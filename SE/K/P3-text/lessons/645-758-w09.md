## The idea in context

Technical performance and affordability interact through duty cycles, degradation, maintenance and resource constraints. Compute lifecycle cost using discounted cash flow, availability effects and scenario-dependent replacements. Be explicit about currency year, perspective, time horizon and discount rate. Expected cost alone can hide unacceptable tail exposures or mission downtime.

## Worked reasoning: apply it to the shuttle case

A $25k upgrade saves $9k/year for four years. At 5% discount rate, present value of savings is about $31.9k, before installation downtime and uncertainty. Whether it is worthwhile also depends on operational service loss during upgrade.

**Assumption to challenge:** Comparing undiscounted budgets with discounted benefits or omitting correlated maintenance downtime. Record what observation or test would expose this failure before using the result in a decision.

2. What is a CER?

<details><summary><strong>Reveal guided answers</strong></summary>

1. **Why start with a WBS?** To define scope, ownership, completeness, and prevent omissions/double counting.

2. **What is a CER?** A relationship that estimates cost from one or more technical/programmatic drivers.

3. **Why integrate dynamic outputs?** Usage, stress, cycles, failures, and downtime create lifecycle costs.
