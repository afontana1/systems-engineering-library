## The idea in context

An integrated model baseline binds parameter files, solver settings, seeds, scenarios, code versions and expected invariants. Before broad experiments, perform convergence, integration, unit and fault tests. Statistical design then chooses factors, uncertainty sources and output criteria. Compute budgets should constrain experiment scope without hiding sensitivity in high-consequence scenarios.

## Worked reasoning: apply it to the shuttle case

A nominal thermal model suggests 35°C battery temperature, but halving the co-simulation step changes it to 41°C. This six-degree discrepancy is a numerical issue to investigate before executing fleet policy experiments.

**Assumption to challenge:** Running expensive Monte Carlo studies on an integration baseline that has not passed step-refinement tests. Record what observation or test would expose this failure before using the result in a decision.

## Test understanding before reading the answers

The next three questions are adapted from the **original guide's Week 7 knowledge check**, with its answer guidance retained so you can learn and self-check in one place.

1. What is a run for record?
2. Why screen first?
3. Why preserve time histories?

<details><summary><strong>Reveal guided answers</strong></summary>

1. **What is a run for record?** An execution from an approved configuration whose result may be used as decision evidence.

2. **Why screen first?** To identify influential factors and interactions before spending runs on detailed characterization.

3. **Why preserve time histories?** Aggregates can hide modes, peaks, transients, event order, and failure mechanisms.

</details>
