# Use M&S to support integration, verification, validation, and test decisions

**Cross-course case:** Fictional Autonomous Campus Shuttle. Figures are synthetic and illustrate reasoning; they do not validate real transport operations.

## The idea in context

Models can support test planning by identifying stress scenarios, expected signatures and measurement sensitivity. But a simulator verified against its own synthetic data does not establish external validity. Link model assertions to independent qualification tests and specify what evidence would refute key assumptions. Separate test of the system from test of the model.

## Worked reasoning: apply it to the shuttle case

The model predicts that dispatch delay doubles when wireless latency exceeds 200 ms. Use that prediction to select bench test conditions, but do not mark the latency requirement verified until measured system evidence exists.

**Assumption to challenge:** Using simulations as circular proof of requirements that were embedded as constraints in the same simulation. Record what observation or test would expose this failure before using the result in a decision.

## Test understanding before reading the answers

The next three questions are adapted from the **original guide's Week 10 knowledge check**, with its answer guidance retained so you can learn and self-check in one place.

1. What is model-supported T&E?
2. What is held-out validation?
3. Why track configuration?

<details><summary><strong>Reveal guided answers</strong></summary>

1. **What is model-supported T&E?** Use of models to design, augment, interpret, or—in authorized cases—provide evidence for test and evaluation decisions.

2. **What is held-out validation?** Evaluation against data not used to calibrate or select the model.

3. **Why track configuration?** Evidence is valid only for the system, model, parameters, environment, and requirement versions represented.

</details>
