The idea in context

Reference modes are time-series patterns: growth, overshoot, oscillation, collapse or goal-seeking. Define units, observation interval and decision horizon before drawing a behavior-over-time graph. Distinguish observation from expectation or stakeholder narrative; annotate structural breaks and data changes. A reference mode constrains possible feedback explanations but does not uniquely determine them.

Worked reasoning: apply it to the shuttle case

Rider demand grows for six months, falls sharply after a service outage, then slowly recovers. A one-month snapshot would miss reputation dynamics; a yearly aggregate might hide the outage shock.

Assumption to challenge: Fitting a feedback story to an unlabeled sketch without examining real timeline and definitions. Record what observation or test would expose this failure before using the result in a decision.

Test understanding before reading the answers

The next three questions are adapted from the original guide's Week 2 knowledge check, with its answer guidance retained so you can learn and self-check in one place.

  1. What is a reference mode?
  2. Must it be quantitative?
  3. Why use several reference modes?

<details><summary><strong>Reveal guided answers</strong></summary>

  1. What is a reference mode? A behavior-over-time pattern the model should help explain for its intended purpose.

  2. Must it be quantitative? No, but qualitative graphs must be labeled as estimates or perceptions.

  3. Why use several reference modes? Different structures can reproduce one curve; coupled behaviors constrain the hypothesis.

</details>
