## The idea in context

Computational verification tests that code implements its conceptual rules. Use deterministic cases with known answers, invariant assertions, conservation checks and extreme parameters. Separate pseudorandom streams by purpose so changes to one part of the code do not quietly rearrange all randomness. Instrument the model for event traces, not only output charts.

## Worked reasoning: apply it to the shuttle case

With zero arrivals, queue length and utilization must remain zero. With one passenger and deterministic 4-min service beginning at t=2, departure must be t=6. If both tests fail, do not run a Monte Carlo campaign.

**Assumption to challenge:** Claiming model credibility because the program runs without exceptions or the animation looks plausible. Record what observation or test would expose this failure before using the result in a decision.

## Test understanding before reading the answers

The next three questions are adapted from the **original guide's Week 6 knowledge check**, with its answer guidance retained so you can learn and self-check in one place.

1. What is computational verification?
2. What is metamorphic testing?
3. Why test zero demand?

<details><summary><strong>Reveal guided answers</strong></summary>

1. **What is computational verification?** Evidence that the executable model correctly implements the specified model and computations.

2. **What is metamorphic testing?** Testing expected relationships between transformed inputs and outputs when exact results are unavailable.

3. **Why test zero demand?** It exposes initialization, spontaneous events, resource leaks, and improper statistics.

</details>
