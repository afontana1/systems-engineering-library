## The idea in context

Parametric models connect design variables, physical units, constraint equations and outputs. They are not spreadsheets copied into model attributes. Declare dimensions, parameter ranges, estimation provenance, uncertainty type and solver assumptions. Verify dimensional consistency and boundary behavior before trusting a sensitivity analysis. An executable constraint is credible only within the model form and calibration range; numerical precision is not empirical accuracy.

## Worked reasoning: apply it to the shuttle case

At 30 km/h, a 5-km route takes 10 min before stops. If boarding and intersections add 6 min, cycle time becomes 16 min. Explicit `distance_km / speed_kmh × 60 + delay_min` constraints prevent a km/h vs m/s unit error.

**Assumption to challenge:** Allowing a parameter equation to silently mix units or treating a calibrated point as a global law. Record what observation or test would expose this failure before using the result in a decision.

## Test understanding before reading the answers

The next three questions are adapted from the **original guide's Week 8 knowledge check**, with its answer guidance retained so you can learn and self-check in one place.

1. What is a value type?
2. What is a binding?
3. Why use an external analytic model?

<details><summary><strong>Reveal guided answers</strong></summary>

1. **What is a value type?** A reusable definition of value semantics such as dimension, unit, quantity kind, constraints, and representation.

2. **What is a binding?** A relationship asserting equality or connection among constraint parameters and model properties.

3. **Why use an external analytic model?** It may provide stronger numerical, statistical, optimization, testing, data, or performance capability while the system model preserves context and traceability.

</details>
