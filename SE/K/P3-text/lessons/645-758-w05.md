## The idea in context

Model interoperability is both a semantic and an engineering governance challenge. Structured model metadata should define variable name, unit, causality, version, initialization and assumptions. MBSE identifies the system configuration, while simulation repositories manage executable models and evidence. XML or a shared repository does not itself guarantee compatible meanings.

## Worked reasoning: apply it to the shuttle case

Two teams both publish a variable named `current`: one means electrical amperes and the other means trip count. A typed interface schema and unit validator prevent accidental connection before co-simulation begins.

**Assumption to challenge:** Treating matching strings and file formats as evidence that models are compatible. Record what observation or test would expose this failure before using the result in a decision.

## Test understanding before reading the answers

The next three questions are adapted from the **original guide's Week 5 knowledge check**, with its answer guidance retained so you can learn and self-check in one place.

1. What is an authoritative source?
2. Why is ‘validated’ insufficient metadata?
3. What is a reusable asset package?

<details><summary><strong>Reveal guided answers</strong></summary>

1. **What is an authoritative source?** The controlled location responsible for a defined class of information.

2. **Why is ‘validated’ insufficient metadata?** Validation is conditional on intended use, domain, referent, and evidence.

3. **What is a reusable asset package?** Source or binary plus metadata, interfaces, dependencies, tests, evidence, limitations, and license/security information.

</details>
