Frame the software architecture within the system architecture

The question to answer

How can an architecture communicate the right choices to different audiences?

Conceptual tutorial

Views answer stakeholder questions

A context view reveals external actors and systems; a container view reveals deployable software responsibilities; a component view details internal modularity; a dynamic view traces runtime collaboration; deployment views reveal networks, nodes and failure zones. These are not alternate drawings of the same abstraction. Do not mistake a SysML logical function for a deployable cloud service or a class.

An Architecture Decision Record (ADR) makes decisions reviewable: context, forces, options, chosen approach, consequences, evidence and reconsideration trigger. Architecture-significant requirements (e.g., latency, availability, auditability) should shape boundaries before programming frameworks are selected. Identify concerns specific to operations, security, field maintenance and stakeholders—not just developers.

Design for change and failure

Ask which decisions are expensive to reverse. Data ownership, synchronization semantics and trust boundaries often matter more than web framework choice. Test major assumptions using a small architecture spike. Keep risks visible when a chosen architecture has no evidence yet.

Worked application: follow the reasoning

Decision record. Centralized event delivery simplifies auditing but depends on the network. Local event buffering improves outage resilience but requires replay ordering and conflict resolution. The ADR compares outage tolerance, operational complexity and privacy exposure, then notes an offline-failure experiment required before acceptance.

Practice before viewing solutions

  1. Who needs a deployment view rather than a class diagram?
  2. What belongs in an ADR?
  3. Give an architecture decision expensive to reverse.

<details> <summary><strong>Show worked answers</strong></summary>

  1. Who needs a deployment view rather than a class diagram? Operations/security staff need nodes, trust zones, scaling and failure dependencies.
  2. What belongs in an ADR? Context, options, rationale, evidence, decision, consequences, status and reconsideration criteria.
  3. Give an architecture decision expensive to reverse. Shared data ownership, cross-region consistency, API contract or trust-boundary placement.

The misconception to avoid

Watch for: Equating a C4 container, a SysML part and an OOAD class destroys abstraction clarity.
