The question to answer

How do automated checks become engineering evidence rather than just green badges?

Conceptual tutorial

A passing pipeline is conditional evidence

Unit tests check local logic; integration tests exercise boundaries; contract tests check producer–consumer expectations; system tests evaluate end-to-end outcomes. Tests must be selected by risk and requirement—not only by ease of automation. A green pipeline can certify wrong assertions if the oracle is weak or the environment is unrealistic. Record input data, build ID, dependency versions and test logs.

Continuous integration should run deterministic checks early, then targeted slower tests for interfaces, concurrency, load, security and end-to-end failure modes. Treat flaky tests as measurement defects to investigate, not nuisance checks to disable. Mutation or fault injection can test whether assertions actually detect incorrect behavior.

Connect to system V&V

Map each test to one or more requirement IDs and track executed evidence separately from planned coverage. A software test for receiving emergency-stop command does not substitute for a vehicle-level stopping-distance test. Controlled test configurations and reviewed exemptions are essential at the handoff.

Worked application: follow the reasoning

CI example. A commit changes trip assignment policy. CI runs policy unit tests, state-transition tests, duplicate-request integration test, OpenAPI contract check and trace-coverage export. A deployment stage refuses promotion if a critical requirement has no current test evidence. The pass report includes repository revision and test tool version.

Practice before viewing solutions

<details> <summary><strong>Show worked answers</strong></summary>

  1. Why is 100% statement coverage insufficient? Coverage does not prove assertions, edge cases, concurrency or requirements correctness.
  2. What should distinguish test plan from evidence? The plan defines intended evidence; execution attaches observed result, build/configuration, data and reviewer.
  3. What should an interface contract test exercise? Payload and semantic compatibility, failures, versions, authorization and edge cases.

</details>

The misconception to avoid

Watch for: Optimizing a green badge can encourage weak tests and ignored failures.

Applied exercise and portfolio handoff

Do: Create CI that runs unit/integration tests and exports a versioned requirement-evidence matrix. Treat this as preparation for the fuller deliverables and rubric in the original Week 10 guide; the companion is not a substitute for those graded artifacts.
