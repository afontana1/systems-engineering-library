Behavior modeling: use cases, activities/actions, interactions, states, and modes

Companion chapter: EN.645.631, Week 05 · Phase 1 edition 1.0 (2026-10-30)
Original course: Introduction to Model Based Systems Engineering — find Week 5 for assignment, assessment criteria and complete reading plan.
Concepts: activity, sequence interaction, state machine, mode
Use of case: Synthetic Autonomous Campus Shuttle case; all values and designs are educational, not field safety guidance.

The question to answer

Why does one system need multiple behavioral views?

Conceptual tutorial

Different questions, different semantics

An activity model asks what actions and control flows occur. An interaction or sequence view asks which participants exchange messages and in what order. A state machine asks which states, transitions, guards and effects are legal over time. These representations overlap but are not interchangeable: a successful trip sequence does not specify what to do when a vehicle enters emergency mode during boarding.

To model behavior consistently, identify an event, precondition, guard, action/effect, postcondition and exceptional path. Use stable behavior identifiers. Distinguish a state such as AwaitingAcknowledgment from an activity such as TransmitRoute. States persist until transitions occur; actions are occurrences that consume time or produce effects.

Check cross-view consistency

If an interaction sends RouteAccepted while the state machine permits acceptance only in Ready mode, the sequence must establish that mode first. If an activity diagram has a Retry branch, identify retry limits and timeout handling in the state model. An independent review should deliberately inject an impossible event or out-of-order message and verify that the model rejects or handles it.

Behavior modeling is also an evidence design activity: each transition and high-risk scenario should eventually map to a test or demonstration.

Worked application: follow the reasoning

Dispatcher behavior. Idle → on request, SelectingVehicle → after selection, AwaitingAck → on acceptance, Assigned. If no acknowledgement arrives within 3 seconds (illustrative value), transition to Reassigning; after two failures, notify an operator. An activity view may show retry loops, but only the state machine makes legal retry counts and modes explicit.

Practice before viewing solutions

  2. How do a sequence and a state machine disagree?
  3. Why are timeout rules behavioral requirements?

<details> <summary><strong>Show worked answers</strong></summary>

  1. Which view best establishes legal event order for a vehicle mode? A state machine with states, transitions, guards and effects.
  2. How do a sequence and a state machine disagree? A sequence may send a command in a state where the machine disallows it, or omit a required acknowledgement.
  3. Why are timeout rules behavioral requirements? They constrain when and how the system must respond to absence of input; they can be specified and tested.

</details>

The misconception to avoid

Watch for: Calling an action a state makes it difficult to express persistence, guards and transitions.
