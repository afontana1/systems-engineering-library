# Model state-dependent behavior and conduct the Analysis Model Review

**Companion chapter:** EN.605.704, Week 06 · Phase 1 edition 1.0 (2026-10-30)  
**Original course:** [Object-Oriented Analysis and Design](../../../C/P1/EN605704.md) — find **Week 6** for assignment, assessment criteria and complete reading plan.  
**Concepts:** finite-state machine, invariant, guard, analysis review  
**Use of case:** Synthetic Autonomous Campus Shuttle case; all values and designs are educational, not field safety guidance.

## The question to answer
> How do we rule out illegal behaviors over the lifetime of an object?

## Conceptual tutorial

### States constrain the event space
A state machine describes which states an object may occupy and which events cause transitions. For a trip: `Requested`, `Confirmed`, `InProgress`, `Completed`, `Canceled`. `CompleteTrip` from `Requested` is invalid. Guards are predicates evaluated before a transition, such as `[vehicle acknowledged]`; effects are actions performed when it occurs. Distinguish rejected events from events silently ignored by policy.

An **invariant** must hold in all applicable states. Examples: a completed trip has a completion timestamp; at most one active assignment exists for a trip; an active trip references a current vehicle. Invariants may span objects and require transaction design later. A state machine explains legal history; it does not make those histories safe automatically.

### Conduct an analysis review
Pick scenarios from weeks 2–5 and attempt to break the models: late cancellation after boarding, lost acknowledgement, repeated assignment, data repair after power loss. Evaluate vocabulary, associations, guards, invariants and testability. Track review findings and close only with evidence. The analysis model is sufficiently mature when key domain meaning and exceptional behavior are stable enough to inform design.

## Worked application: follow the reasoning

**State conflict.** The notification event `AssignmentAccepted` arrives after a trip was canceled. An unconstrained handler might revive a canceled trip. A state machine rejects the transition `Canceled → Confirmed` unless an explicit reinstatement use case exists; versioned commands can also prevent accepting stale acknowledgements.

1. **Why is `Cancel` not always legal from every trip state?** Cancellation semantics differ before/after boarding and may require alternative procedures.
2. **What distinguishes a guard from an invariant?** A guard controls one transition; an invariant is a property expected to hold across all relevant states.
3. **What should an analysis-model review challenge?** Inconsistent meanings, missing exceptions, impossible multiplicities, unmodeled states and unsupported assumptions.

## The misconception to avoid

**Watch for:** Assuming sequences alone prove state correctness misses interleavings and illegal histories.
