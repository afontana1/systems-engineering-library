# Define the software systems engineering role and establish the baseline

**Companion chapter:** EN.645.764, Week 01 · Phase 1 edition 1.0 (2026-10-30)  
**Original course:** [Software Systems Engineering](../../../C/P1/EN645764.md) — find **Week 1** for assignment, assessment criteria and complete reading plan.  
**Concepts:** system-to-software allocation, software baseline, stakeholder concern, assurance  
**Use of case:** Synthetic Autonomous Campus Shuttle case; all values and designs are educational, not field safety guidance.

## The question to answer
> Which engineering obligations become software responsibilities?

## Conceptual tutorial

### Software exists inside a larger system
Software systems engineering translates mission and system-level constraints into software scope, interfaces, quality evidence, delivery and operations. A vehicle control function, a dispatch feature and a safety procedure may be in different organizations yet form one passenger service. The engineer has to identify which outcomes software can guarantee and which depend on hardware, networks, humans or regulations.

A useful initial baseline lists source system needs, software allocated requirements, interface responsibilities, operating environment, assumptions, verification strategy, current design decisions and unresolved gaps. Avoid claiming that 'the platform ensures vehicle safety' when it merely sends requests to a separate safety-authorized subsystem. Trace external authority and expected fail-safe behavior.

### Set an evidence contract
For each software claim identify the observation that would challenge it: architecture review, unit/integration tests, load experiments, incident rehearsal, vulnerability assessment or operational demonstration. Mark evidence not yet produced. Product backlogs are useful planning tools; they do not by themselves prove system-level completeness or compliance.

## Worked application: follow the reasoning

**Boundary scenario.** The dispatch service can promise to validate a route command schema and retry delivery; it cannot guarantee a vehicle has physically stopped. A software baseline links `SW-REQ-07` to the system stop requirement but explicitly records the onboard controller's authority and an acknowledgement/interface test.

## Practice before viewing solutions

1. What is software allocation?
2. What should be included in the initial software baseline?
3. Why is a backlog not an assurance argument?

<details>
<summary><strong>Show worked answers</strong></summary>

1. **What is software allocation?** Assignment of part of a system function or obligation to software, with dependencies and interfaces.
2. **What should be included in the initial software baseline?** Sources, requirements, allocated responsibilities, interfaces, decisions, assumptions, risks, planned evidence and revision.
3. **Why is a backlog not an assurance argument?** Tasks and priorities do not establish that critical requirements have been verified or hazards controlled.

</details>

## The misconception to avoid

**Watch for:** Inflating software responsibility to encompass hardware or human outcomes destroys clear interface accountability.
