Specify and analyze performance, networking, real-time, security, and privacy constraints

Companion chapter: EN.645.764, Week 08 · Phase 1 edition 1.0 (2026-10-30)
Original course: Software Systems Engineering — find Week 8 for assignment, assessment criteria and complete reading plan.
Concepts: latency budget, threat model, privacy, real-time constraint
Use of case: Synthetic Autonomous Campus Shuttle case; all values and designs are educational, not field safety guidance.

The question to answer

How do constraints interact when software meets networks and people?

Conceptual tutorial

Budget end-to-end behavior

Break a response requirement into acquisition, queuing, transport, computation, storage and actuation or display. Allocate numerical budgets with units and margin. Then analyze what happens under contention and failure. Average latency is rarely adequate when a requirement specifies a 99th percentile or a hard real-time deadline; measurement design needs representative loads and credible timestamp synchronization.

Security and privacy constraints have the same systems flavor. Identify assets, actors, trust boundaries, abuse cases and controls. A token accepted by an API does not necessarily authorize a rider to view another person's trip. Apply least privilege and threat modeling at each interface. Collect only necessary personal data, set retention periods and show how deletion propagates to backups and analytics where applicable.

Make tradeoffs explicit

Encryption, audit logging and redundancy may add latency or storage requirements. Do not solve them by removing security; measure and redesign the budget. For a safety-related function, distinguish hard deadlines from convenience-level updates and allocate fault responses to the authorized components.

Worked application: follow the reasoning

Timing case. Rider status budget: ingress 80 ms, queue 150, processing 120, database 100, outgoing network 200 = 650 ms nominal under a 900 ms target, leaving 250 ms. At 99th percentile the queue can exceed 450 ms; test under burst load. The controller's emergency-stop deadline is a separate safety function and should not share this best-effort service assumption.

The misconception to avoid

Watch for: A single secure-and-fast architecture diagram conceals incompatible and unmeasured constraints.
