Knowledge lenses for this course

  • Software quality attributes and architectural tactics — Quality attributes describe how well software must behave under conditions: latency, availability, security, recoverability, maintainability, usability and more.
  • CI/CD, configuration, and software assurance — A reliable software delivery pipeline transforms controlled source into repeatable build artifacts and test evidence.
  • Requirements traceability and impact analysis — Traceability is a justified network of relationships among needs, requirements, functions, design elements, tests, risks and decisions.
  • Interface control and integration contracts — An interface control definition specifies what crosses a system-element boundary and under what rules.
  • Allocation, coverage, and design responsibility — Allocation connects obligations and functions to design elements that will fulfill them.
  • Risk, issue, uncertainty, and opportunity — A risk is an uncertain future event or condition that could affect objectives; an issue is a condition already present that requires action.

Phase 4 technical reading: Safety software and dependability reading

For the week 9 dependability, safety, resilience and supply-chain argument, use the full causal safety chapter, which distinguishes hazard constraints from component failures and derives a quantitative common-cause counterexample. The connected baseline case supplies an evidence-to-hazard audit; students should record operational modes and untested paths rather than treating link coverage as assurance.

Best supporting shelf for this course

  • Guide to the Systems Engineering Body of Knowledge — Breadth-first conceptual encyclopedia and pointers to further references.
  • OMG SysML formal specifications — Precise notation and semantics; consult when you need authoritative modeling constructs; not a beginner textbook.
  • OMG UML formal specification — Formal language definition for software structure, interaction and behavior models.
  • CMU SEI: Early Analysis of Software Architecture — Detailed quality-attribute and architectural reasoning studies.
  • NIST SP 800-160 Rev. 1 — Engineering Trustworthy Secure Systems — Security and trustworthiness integrated with engineering lifecycle reasoning.
