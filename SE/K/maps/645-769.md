## Knowledge lenses for this course

- [Verification, validation, and acceptance](../encyclopedia/v-and-v.md) — Verification asks whether the system or element meets specified requirements; validation asks whether it satisfies intended use and stakeholder needs.
- [Verification cross-reference matrices and test design](../encyclopedia/verification-matrix.md) — A verification cross-reference matrix (VCRM) links each controlled requirement to verification method, level, procedure, success criterion, configuration and evidence.
- [Integration build-up and readiness evidence](../encyclopedia/integration-strategy.md) — Integration is the progressive assembly of elements into a functioning system while checking their interactions.
- [Simulation verification, validation, and credibility](../encyclopedia/model-vv-and-credibility.md) — Simulation verification asks whether the implementation represents the conceptual model correctly; simulation validation asks whether that model adequately represents reality for its intended use.
- [Probability, distributions, and dependence](../encyclopedia/probability-and-dependence.md) — An uncertain quantity is not defined by its mean alone.
- [Risk, issue, uncertainty, and opportunity](../encyclopedia/risk-vs-issue.md) — A risk is an uncertain future event or condition that could affect objectives; an issue is a condition already present that requires action.

## Direct technical methods for test evidence

Use [statistical inference and factorial experiments](../methods/statistical-inference-and-experiments.md) when the week's verification planning requires estimation, uncertainty, test factors, and independent replication. For survival or life-testing evidence, use [censored reliability analysis](../methods/reliability-and-censored-evidence.md). These methods complement—not replace—the governed test plan and requirement-specific acceptance decisions.

## Phase 4 technical reading: Test sufficiency across baselines

For week 12's evidence review, compare the two synthetic builds in the [connected case](../methods/campus-mobility-engineering-case.md) using the [model-currency auditor](../methods/model-baselines-and-evidence.md). A passing rehearsal at 1.74 s is not a validated field-load tail estimate; evidence acceptance must explain measurement, sampling, relevant configuration, and unresolved hazard paths.

## Phase 5 technical reading: Review evidence and unresolved hazards as artifacts

The [Campus Mobility specification/ICD/VCRM package](../methods/campus-mobility-engineering-artifacts.md) keeps one controlled requirement set, interface freshness limits, test provenance, hazard defeaters and CM-B3 change assessment. Use the files in readiness reviews; current evidence and safety argument limitations must be assessed rather than counted.
