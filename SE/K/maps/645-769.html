Knowledge lenses for this course

  • Verification, validation, and acceptance — Verification asks whether the system or element meets specified requirements; validation asks whether it satisfies intended use and stakeholder needs.
  • Verification cross-reference matrices and test design — A verification cross-reference matrix (VCRM) links each controlled requirement to verification method, level, procedure, success criterion, configuration and evidence.
  • Integration build-up and readiness evidence — Integration is the progressive assembly of elements into a functioning system while checking their interactions.
  • Simulation verification, validation, and credibility — Simulation verification asks whether the implementation represents the conceptual model correctly; simulation validation asks whether that model adequately represents reality for its intended use.
  • Probability, distributions, and dependence — An uncertain quantity is not defined by its mean alone.
  • Risk, issue, uncertainty, and opportunity — A risk is an uncertain future event or condition that could affect objectives; an issue is a condition already present that requires action.

Direct technical methods for test evidence

Use statistical inference and factorial experiments when the week's verification planning requires estimation, uncertainty, test factors, and independent replication. For survival or life-testing evidence, use censored reliability analysis. These methods complement—not replace—the governed test plan and requirement-specific acceptance decisions.

Phase 4 technical reading: Test sufficiency across baselines

For week 12's evidence review, compare the two synthetic builds in the connected case using the model-currency auditor. A passing rehearsal at 1.74 s is not a validated field-load tail estimate; evidence acceptance must explain measurement, sampling, relevant configuration, and unresolved hazard paths.

Phase 5 technical reading: Review evidence and unresolved hazards as artifacts

The Campus Mobility specification/ICD/VCRM package keeps one controlled requirement set, interface freshness limits, test provenance, hazard defeaters and CM-B3 change assessment. Use the files in readiness reviews; current evidence and safety argument limitations must be assessed rather than counted.
