## The engineering question

> How do requirements and stakeholder outcomes become defensible test objectives?

## Conceptual tutorial

### Every test starts with an assertion
Create a crosswalk from requirement ID and revision to observable parameter, condition, threshold, method, article, procedure and acceptance authority. For validation, trace mission outcomes to representative scenarios, users and operational contexts. A critical test parameter is a measure whose value materially affects compliance, safety or mission utility; it needs controlled definition and measurement capability.

Different levels of evidence cannot be substituted without argument. A test of a software module supports claims about that module under its setup, not automatically the integrated system. An analytic proof is only as strong as its assumptions and inputs; an inspection cannot establish dynamic response time. Plan combinations of analysis, inspection, demonstration and test where the requirement demands it.

### The denominator and environment matter
A claim such as "at least 99% within 900 ms" requires specifying which requests count, the workload distribution, timing origins, data exclusions, and confidence/risk of the estimator. Define these *before* collecting data. A test can have a high pass percentage while ignoring requests that time out and vanish from logs.

## Worked example: follow the reasoning

**Crosswalk.** `R-14/revC` → parameter `T_status = timestamp(event_issued) − timestamp(request_received)` → eligibility includes all accepted requests in `WL-01` → criterion empirical 99th percentile ≤ 900 ms under an approved statistical sampling plan. Artifacts are a controlled execution script, raw event logs, clock-verification record and an analysis report with excluded trials disclosed.

## Retrieval questions — attempt these first

1. What distinguishes an objective from a procedure?
2. Why does excluded-timeout handling matter?
3. What must a critical test parameter define?

<details><summary><strong>Reveal explained answers</strong></summary>

1. **What distinguishes an objective from a procedure?** Objective specifies the claim to resolve; a procedure implements an evidence-gathering method.
2. **Why does excluded-timeout handling matter?** Ignoring timed-out requests biases the distribution toward successful outcomes.
3. **What must a critical test parameter define?** Quantity, unit, reference, condition, threshold, accuracy and decision relevance.

</details>

## Critical misconception

**Watch for:** Percent pass among only completed successful records cannot support a whole-population reliability claim.
